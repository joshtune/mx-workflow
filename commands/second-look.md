# Second Look

The review layer that sits on top of whatever generated the code. Point it at a PR (or diff) produced by another agent — Claude Tag, Cursor, Copilot, Aider, a teammate — and it runs the full mx review team on output you didn't write.

Because the author is an AI you didn't supervise, this command **leans harder on the interrogators**: hallucination checking and silent-failure hunting run with extra weight, since invented APIs and swallowed errors are exactly what unsupervised generation produces.

It is **read-only** — it never pushes commits or modifies the PR.

**Options:** $ARGUMENTS

## Step 1: Resolve the Input

Determine what to review (PR is the primary, default path):

| Input | How to fetch the diff |
|-------|----------------------|
| `<number>` or PR url *(default)* | `gh pr diff <n>` for the patch; `gh pr view <n> --json title,author,headRefName,files` for context |
| `--diff <file>` | Read the patch file directly |
| `<base>..<head>` or a sha | `git diff <base>..<head>` (works offline, no `gh`) |

If `gh` is needed but unavailable or unauthenticated, say so and suggest `--diff`/range as the offline path. Capture the **author** when you can — surface it in the report ("reviewing Claude-Tag-authored PR #214"), since the whole point is reviewing un-self-authored code.

## Step 2: Run the Review Team

Run the same 8 review-grade agents as `/mx:review`, over the resolved diff, in parallel via the Task tool — with these emphases for externally-generated code:

**Run with extra weight (un-supervised author → highest hallucination/error risk):**
- **mx-silent-failure-hunter** — swallowed errors, fake fallbacks, mock code left in
- A **hallucination pass** equivalent to `/mx:hallucination-check` over the diff — invented APIs, non-existent imports, wrong signatures, cross-referenced against installed deps

**Always run:**
- **mx-code-reviewer**, **mx-performance-auditor**, **mx-quality-keeper** (structural checks where the code can be checked out)

**Run if applicable:**
- **mx-type-design-analyzer** (types changed), **mx-mr-test-analyzer** (tests changed), **mx-comment-analyzer** (comments changed)

**Report-only:**
- **mx-code-simplifier** — suggestions only; never edits the PR

Normalize severities exactly as `/mx:review` does (CRITICAL / HIGH / MEDIUM / INFO).

## Step 3: Verdict & Report

Apply the **balanced** verdict by default (REJECT on CRITICAL, WARNINGS on HIGH); honor `--strict`/`--advisory` if passed. Always include a recommendation with reasons.

Save the report to `.agents/reports/second-look-{YYYY-MM-DD}.md`.

```
SECOND LOOK
===========
Target:   PR #214 "Add billing webhooks" · author: claude-tag · 7 files
Mode:     balanced

VERDICT:  PASS / PASS WITH WARNINGS / REJECT

Recommendation:
  <what to do and why — e.g. "Request changes: webhook handler swallows
   signature-verification failures (billing.ts:54) and imports a non-existent
   Stripe method (billing.ts:12)">

FINDINGS
────────
[CRITICAL] billing.ts:54 — signature check failure caught and ignored (mx-silent-failure-hunter)
[HIGH]     billing.ts:12 — `stripe.webhooks.constructEventAsync` not in stripe@14 (hallucination)
[INFO]     billing.ts:88 — nested ternary could be a lookup (mx-code-simplifier, report-only)
```

When reviewing a PR, optionally offer to post the verdict as a PR review comment via `gh pr comment` — but **only if the user confirms**; never post automatically.
