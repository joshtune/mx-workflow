The mx-workflow Slack bot turns a Mac mini into an autonomous build server. Send a message in Slack, and Claude Code runs the full `/mx:build --auto` pipeline — discovery, PRD, plan, test-first build, QA, and commit — streaming progress back to you in real-time.

## Architecture

```
You (Slack #builds) → Slack Bot → Claude Code + /mx:build --auto → GitHub PR → Slack (progress + result)
```

| Component | Role |
|---|---|
| **Slack bot** (`slack-bot/index.js`) | Listens to #builds channel and @mentions, dispatches build requests |
| **Runner** (`slack-bot/runner.js`) | Spawns Claude Code with `--print` and `--dangerously-skip-permissions`, streams output |
| **mx-workflow** | The plugin — `/mx:build --auto` handles the full pipeline |
| **launchd daemon** | Keeps the bot running on boot, auto-restarts on crash |

## How it works

1. You send a message in `#builds`: _"Build a task management system with admin and user roles"_
2. The bot confirms and creates a live log thread in Slack
3. Runner spawns `claude --print --dangerously-skip-permissions` with `/mx:build --auto`
4. `/mx:build --auto` runs the full pipeline:
   - **Discovery** — infers stack, scope, and roles from the instruction
   - **PRD** — generates spec with User Roles & Expectations (commit: `docs(prd): ...`)
   - **Plan** — codebase-aware implementation plan (commit: `docs(plan): ...`)
   - **Build** — test-first, auto-selects agent team or single-agent (commit: `feat: ...`)
   - **QA** — spec conformance per role, test coverage, structural checks (commit: `fix: ...` if needed)
5. Output streams to Slack every 3 seconds (debounced to avoid rate limits)
6. On completion, the bot posts the branch name and PR link

## Triggers

| Trigger | How |
|---|---|
| **#builds channel** | Any message in the channel kicks off a build |
| **@mention** | Mention the bot in any channel with an instruction |
| **Slash command** | `/build <what to build>` from anywhere |

## Session isolation

Each build runs in its own directory under `$MX_WORK_DIR/session-<id>/`. This means:
- Builds don't interfere with each other
- Each session has its own git repo
- Logs are stored per session in `$MX_LOG_DIR/<session-id>.log`

## Setup

See the full setup guide at [`slack-bot/SETUP.md`](https://github.com/joshtune/mx-workflow/blob/main/slack-bot/SETUP.md). The key steps:

1. Create a Slack app with Socket Mode, bot scopes, and event subscriptions
2. Configure `.env` with tokens and paths
3. `npm install` and test with `node index.js`
4. Install the launchd daemon for auto-start on boot
5. Set up Tailscale for remote SSH access from your MacBook

## Remote monitoring

Tail live build logs from your MacBook:

```bash
# All bot output
ssh mac-mini "tail -f ~/builds/.logs/slack-bot.log"

# Specific build session
ssh mac-mini "tail -f ~/builds/.logs/<session-id>.log"
```

## Requirements

- macOS (Mac mini, headless)
- Node.js 20+
- Claude Code CLI
- mx-workflow plugin installed
- GitHub SSH configured
- Slack workspace with a bot app
