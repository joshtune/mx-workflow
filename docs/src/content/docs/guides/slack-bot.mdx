title: Slack Bot (Headless Builds)
description: Run builds on a Mac mini triggered from Slack — interactive by default, or fully autonomous with --auto.
---

The mx-workflow Slack bot turns a Mac mini into a build server you control from Slack. Send a message in Slack, and Claude Code runs the `/mx:build` pipeline — with you reviewing and approving each phase in the thread, or fully autonomous with `--auto`.

## Two modes

| Mode | Trigger | Behavior |
|---|---|---|
| **Interactive** (default) | Any message without `--auto` | Runs phase-by-phase, posts results to the thread, waits for your approval or feedback at each gate |
| **Auto** | Add `--auto` to your message | Fire-and-forget — runs the full pipeline autonomously, streams output, posts final result |

## Architecture

```
You (Slack #builds) → Slack Bot → Claude Code (per phase or full pipeline) → GitHub PR → Slack thread
```

| Component | Role |
|---|---|
| **Slack bot** (`slack-bot/index.js`) | Listens to #builds channel and @mentions, routes thread replies to active sessions |
| **Session manager** (`slack-bot/session.js`) | Tracks build state, persists to disk, survives restarts |
| **Interactive runner** (`slack-bot/interactive.js`) | Drives sessions through phases, mediates conversation at each gate |
| **Phase prompts** (`slack-bot/phases.js`) | Generates per-phase Claude prompts, parses structured output, classifies replies |
| **Runner** (`slack-bot/runner.js`) | Spawns Claude Code with `--print`, streams output |
| **mx-workflow** | The plugin — `/mx:build` handles the pipeline |
| **launchd daemon** | Keeps the bot running on boot, auto-restarts on crash |

## Interactive mode (default)

When you send a message without `--auto`, the bot runs each phase as a separate Claude invocation and pauses between them for your input:

```
You:  "dashboard: add a settings page with theme toggle"
Bot:  → Runs discovery → posts questions to thread
You:  "web app, yes backend, per-user settings"
Bot:  → Infers context → posts summary, asks "proceed?"
You:  "go"
Bot:  → Generates PRD → posts summary with must-haves
You:  "add a reset-to-defaults button as a must-have"    ← feedback loop
Bot:  → Re-generates PRD with your feedback → posts updated summary
You:  "approved"
Bot:  → Generates plan → posts summary with file count, strategy
You:  "approved"
Bot:  → Runs build + QA + report (phases 3-5 as one block)
Bot:  → Posts final result with branch and PR link
```

At each gate you can:
- **Approve** — say "yes", "approved", "go", "lgtm", etc. to proceed
- **Give feedback** — describe changes and the phase re-runs with your feedback incorporated
- **Cancel** — say "cancel" or "stop" to abort the build

### Session persistence

Sessions are saved to disk as JSON files. If the bot restarts while waiting for your review, it picks up where it left off — just reply in the thread. Sessions expire after 24 hours.

### Identity check

Only the user who started the build can approve or give feedback in that thread. Other users get a polite message pointing them to the session owner.

## Auto mode

Add `--auto` to your message for the original fire-and-forget behavior:

```
"dashboard: add dark mode --auto"
```

1. The bot confirms and creates a live log thread
2. Runner spawns `claude --print` with `/mx:build --auto`
3. `/mx:build --auto` runs the full pipeline — discovery, PRD, plan, build, QA
4. Output streams to Slack every 3 seconds (debounced to avoid rate limits)
5. On completion, the bot posts the branch name and PR link

## Triggers

| Trigger | How |
|---|---|
| **#builds channel** | Any message in the channel kicks off a build |
| **@mention** | Mention the bot in any channel with an instruction |
| **Slash command** | `/build <what to build>` from anywhere |

## Session isolation

Each build runs in its own directory under `$MX_WORK_DIR/session-<id>/`. This means:
- Builds don't interfere with each other
- Each session has its own git repo
- Logs are stored per session in `$MX_LOG_DIR/<session-id>.log`

## Project resolution

The bot knows which project to work on via four reference patterns:

| Pattern | Example | How it works |
|---|---|---|
| **Project prefix** | `dashboard: add dark mode` | Parses alias before the colon |
| **First word** | `api fix the webhook bug` | First word matched against known aliases |
| **Default project** | `fix the login bug` | Uses the configured default when no project specified |
| **Explicit flag** | `--repo billing add export` | Override with `--repo` flag |
| **New project** | `Build a new SaaS billing system` | Detected by "build a/create a" pattern, creates fresh session |

Project aliases are configured via `/mx:setup-mac-mini`, which scans your repos, lets you name them, and writes `.mx-mac-mini.json`.

## Setup

Run `/mx:setup-mac-mini` on day one. It handles everything in 6 phases:

| Phase | What it does |
|---|---|
| **1. System prerequisites** | Checks and installs Homebrew, Node.js 20+, Claude Code CLI, Git/SSH, tmux, Tailscale, mx-workflow plugin |
| **2. Slack integration** | Guides you through creating a Slack app, collects tokens, writes `.env`, auto-detects bot user ID, tests connection |
| **3. Project registration** | Scans for repos, creates aliases, sets default project, validates CLAUDE.md |
| **4. Daemon setup** | Configures launchd to run the bot on boot with auto-restart |
| **5. Verification** | Tests project routing, Slack connection, and Claude Code readiness |
| **6. Summary** | Shows everything configured and how to use it |

For manual reference, see [`slack-bot/SETUP.md`](https://github.com/joshtune/mx-workflow/blob/main/slack-bot/SETUP.md).

## Remote monitoring

Tail live build logs from your MacBook:

```bash
# All bot output
ssh mac-mini "tail -f ~/builds/.logs/slack-bot.log"

# Specific build session
ssh mac-mini "tail -f ~/builds/.logs/<session-id>.log"
```

## Requirements

- macOS (Mac mini, headless)
- Node.js 20+
- Claude Code CLI
- mx-workflow plugin installed
- GitHub SSH configured
- Slack workspace with a bot app
